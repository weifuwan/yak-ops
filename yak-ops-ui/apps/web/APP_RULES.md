# Web App Rules

Status: Active

Scope: `yak-ops-ui/apps/web/**`。

目录与产品入口职责见 [Architecture](../../ARCHITECTURE.md)，通用限制见 [Frontend Rules](../../FRONTEND_RULES.md)。本文件只维护 App 层交互与状态约束。

## App Domain

任务定义、Task Detail 与运维入口分离，复用 `app/data-sync` 的共享实现，不复制离线/实时编辑器或 Execution 展示组件。Task Detail 留在数据集成内，只读展示当前 Task 的 Execution / Attempt 运行事实；离线与实时 Task Detail 统一使用左侧 Execution 列表与右侧详情的 master-detail 布局，右侧 PageHeader 固定，详情区域独立滚动，当前 Execution 仍通过 URL 查询参数保持可恢复。OFFLINE Task 列表允许对已上线且无活动 Execution 的任务执行一次手工运行；Editor 和 Task Detail 不承载运行/停止命令，REALTIME Start / Stop 与 Schedule Runtime 也不因此迁入数据集成页面。跨 Task 观察仍由运维中心负责。任务发布与执行语义见 [Data Sync Contract](../../../docs/capabilities/data-sync/README.md)；表单遵循 [Form Rules](FORM_RULES.md)。

Task Detail 的信息层级优先“执行结果 → 失败原因 → 指标 → 排障细节”：主视图不直接展示内部 Execution ID；失败原因前置到执行概览；仅在存在真实重试或等待重试时展示重试记录。选中 Execution 的前两个 Tab 统一为 `执行情况 / 配置快照`；第三个 Tab 按同步类型区分：OFFLINE 为 `执行诊断`，REALTIME 仍为 `执行日志`。OFFLINE 诊断消费 Runtime Trace Summary、Source Split 与 Sink Batch API，并将既有生命周期事件折叠为辅助审计信息；`配置快照` 必须读取该 Execution 的冻结 definitionSnapshot，而不是当前 Task 定义，并按 `数据来源 / 数据去向 / 执行策略` 分组。Source 只承载读端与 Connector Source 参数，Sink 只承载写端与 Connector Sink 参数，Execution Strategy 承载版本、Checkpoint、超时与 Retry 等运行策略；前端只基于现有 Snapshot 字段分组展示，不在本层发明新的后端配置模型。readRows / writeRows 继续遵循后端持久化指标语义。

## App Shell

- 认证后产品复用同一参数化 AppLayout。数据集成、运维中心为 Workspace-scoped，管理中心不受当前 Workspace gate，也不显示 Workspace Switcher。
- Workspace-scoped Outlet 按当前 Workspace 身份重建，防止列表、选择和表单状态跨空间泄漏。页面填充父容器，不自行用 `calc(100vh - ...)` 扣减 Shell 高度。
- Router 只负责 URL 到产品入口的装配；Context 只持有应用级运行态。
- `navigation.ts` 定义完整产品 Registry；User Preference 只存稳定 product id，不复制标签、路由和图标。

## Product Launcher

- 一级真实产品只显示 `PRODUCT_MENU` 中当前用户收藏、且 Registry 仍存在的产品，按服务端 `sortOrder` 排列；无收藏显示空态，不注入默认产品。
- `所有产品` 是独立 `view-all` 入口，不混入真实产品数组。二级展示完整 Registry，收藏变更立即反映到一级。
- 收藏请求由 `service/preference` 承担。允许乐观更新；失败只回滚对应产品，不覆盖其他已完成变更。跨登录、跨设备持久化由服务端负责。
- 一级收藏产品支持快速取消：鼠标悬停或键盘聚焦该 Item 时，右侧显示 `X`；点击只更新该产品的 `favorite=false`，不得触发产品导航或关闭 Launcher。一级与二级必须复用同一收藏 mutation 与 optimistic rollback，禁止维护第二套本地删除状态。
- 两级菜单是 overlay，不改变 Sidebar / Outlet 布局，不增加外层阴影。二级必须紧贴同一 Launcher Track 的右边缘；Track 承担共同位移，关闭先收二级、再短暂错峰滑动 Track，全程不能产生中间空隙。
- 默认 Sidebar 不被关闭后的深色层残留遮挡。菜单触发器有 pointer，打开后原位切换为 X；X、Escape、路由变化、一次空白区点击都能关闭完整 Launcher。
- 二级打开时 `view-all` 保持激活。具体宽度、配色和时序在 [ProductLauncher](app/layout/ProductLauncher.tsx) 与 [AllProductMenu](app/layout/AllProductMenu.tsx) 维护，不在 Architecture 再复制参数表。

## Product Sidebar

菜单使用整行而非圆角卡片；选中态包含浅色背景、右侧高亮线和加粗文字，图标随选中状态变化。非选中项使用普通字重与轻量 hover；保留分组标签。

实际字体、间距与色值在 [ProductSidebar](app/layout/ProductSidebar.tsx) 维护；非选中图标跟随普通文字，选中图标使用高亮。

## Login Page

[登录页](app/login/index.tsx) 顶部使用 Yak UI 的 SplitSparkIcon，中文标题保留 Yak Ops 产品名；不修改 Shell 品牌资源，也不为对齐参考视频添加未接入的注册、第三方登录、找回密码或持久登录入口。账号含义仍是用户名，不改成邮箱校验。公共认证表单使用 large + underlined 控件及 FloatingLabelField，只有单一登录操作，不套用普通管理表单的紧凑横排。提交按钮采用登录页局部的中性深色主题与胶囊布局，颜色取自已有 Token，不改变共享 Button 默认样式或其他页面主色。

右侧按顶部标识/表单与底部账号入口分区，底部使用正常文档流及弹性留白，不绝对定位覆盖表单。页面自身承接纵向滚动，矮屏、软键盘和浏览器放大后内容仍可达；小屏保留产品名和完整表单，不依赖插画表达身份。

字段 Label / Error 复用 Yak UI Field 组件；标签通过 FloatingLabelField 组合，在输入及显隐按钮所在区域聚焦或原生控件有值时上浮，底线和输入区域不变高，不重复显示 placeholder 文案。登录控件使用原生非受控值，提交时从输入引用读取同一次凭证快照，再执行原有校验/请求；避免无事件自动填充在聚焦、显隐或错误重渲染时被旧 React 值覆盖，不向动画传递凭证。用户名与密码下方始终保留错误提示空间，短错误出现或清除不挤动标题和提交按钮；空间可以随长文案或文字缩放增长，不能固定高度裁切。校验失败不发请求，并将焦点移到首个无效输入框。保留 autocomplete、必填和错误关联语义；忙碌提示放在 aria-busy 表单外的状态区域，按钮继续由共享组件保留可访问名称与防重操作。服务端或网络失败仍由统一请求处理提示，不重复弹错。

账号获取入口由登录页私有 [WeChatQrHelp](app/login/WeChatQrHelp.tsx) 承载，位于表单之外，继续使用现有微信公众号二维码；悬停、点击、键盘打开、Escape 关闭和焦点恢复交给 Yak UI Popover，不在页面维护另一套悬停计时器。弹层具有标题与说明，图片不裁切，加载失败提供可读提示；触发器有可见键盘焦点。

密码显隐继续由 Yak UI PasswordInput 管理，renderVisibilityIcon 只替换图形。登录页私有 [LoginPasswordEye](app/login/LoginPasswordEye.tsx) 只接收显隐标记：隐藏密码时睁眼并有界跟随鼠标，明文时闭眼带睫毛；不添加随机眨眼，不读取输入值。跟随只在页面可见、细鼠标且允许动画时启用，指针采样合并到单次 RAF，不逐帧更新登录页 React 状态。离开、滚动、隐藏、减少动画、显隐及卸载时取消待处理任务并复位；快速切换不积累动画。减少动画即时显示正确图形，触屏不跟随。按钮实际点击区域与图形尺寸分开，鼠标切换保持输入选区，键盘切换不抢焦点；左侧插画状态接口和优先级保持原样。

页面验收覆盖空提交、只缺密码、逐项纠错、原生 Enter 提交、Tab / Shift+Tab 顺序、键盘打开/关闭二维码、二维码加载失败、自动填充后的提交、慢请求和重试。增加标签初始/聚焦/有值失焦/清空回落、无事件填充后显隐与失败重试、密码选区、眼睛跟随边界/快速睁闭和运行中切换减少动画的验收。对比校验前后标题/输入框/按钮的位置；检查桌面、平板、窄屏、矮屏和浏览器缩放下内容可达且无横向溢出。减少动画偏好下刷新后验证表情、登录反馈等待与共享加载指示；完整产品和辅助技术验收不能用控件适配器夹具代替。

## Login Scene

登录插画由 [LoginCharacters](app/login/LoginCharacters.tsx) 私有维护，不进入共享 Yak UI。场景整体定位角色群，SVG 下边缘与角色共用的落地基线对齐；底部保留场景留白，不通过逐个平移角色抬高构图。缩放同时受可用宽度与视口高度约束，矮屏不裁掉默认角色轮廓；小屏继续由登录页隐藏插画。

橙色角色的出场终点、待机变形与减少动画模式共用同一套静态轮廓基准，调整饱满度时同步校准眼睛、眨眼和各嘴型的相对位置。保留角色遮挡顺序和黄色长嘴的轮廓外延伸；静态校准不顺带修改表单状态、鼠标跟随系数或动画时序。几何参数留在实现中，不在规则里复制参数表。

入场由登录页私有 [login-entrance](app/login/login-entrance.ts) 按经过时间纯采样，父场景复用同一 RAF 渲染；不再混用 CSS 入场时钟、角色计时器和累计帧数。首次渲染即使用起始形状，不能先闪现完整角色再缩回。静态轮廓基准只有一个定义位置，输入、显示密码、普通跟随与结果反馈不由入场模块重新定义。

四个角色错峰成形：蓝色斜方块向右转正，短暂停留后向上展开并收稳，五官后显且不随身体拉伸；黑色倒挂，带眼睛的一端经左侧翻到上方，长条同时弯曲，落地后小幅回摆并恢复笔直；橙色小胶囊沿右上、右下弧线飞来，落地连续变为小半圆，在固定底边上长大再回收，不增加第二次离地跳跃；黄色先保持矮圆顶，再增加下方身体长度，五官独立完成斜嘴、短暂双眼及单眼过渡。黄色额外眼点仅在入场使用，只裁剪该眼点，不裁剪长嘴，也不接入随机眨眼。

空中轨迹与落地支点分开计算，不以运动中的包围盒作为支点；保留当前角色层次和左侧场景裁切，不移动整页布局来容纳轨迹。入场完成时身体路径、变换、五官及显隐准确回到既有基准，再平滑接入最新指针目标。入场未完成时允许采样指针，但不应用跟随或随机眨眼。

输入关注、显示密码、提交与结果可立即结束入场；同一次状态提交清除倒挂角度、临时变形、额外眼点和五官隐藏，再交给已有场景姿态，不阻塞认证，也不在框间切换、隐藏密码或失败重试时重播。页面或响应式布局在入场中隐藏时完成本次入场，回来不补播。减少动画直接呈现对应静态姿态；运行中开关偏好不重播入场或重复启动 RAF；卸载清理监听、观察器和动画循环。

鼠标与姿态跟随按 RAF 时间差计算：蓝黑眼部使用无回弹的时间平滑，橙色保留有阻尼的时间积分弹性跟随。长帧限制积分跨度，长时间挂起后丢弃旧弹性速度，不用积攒的帧数追赶。普通待机、输入关注与显示密码分别定义目标姿态；黄色遵循固定轮廓与整脸跟随约束；不要通过增加动作幅度掩盖时间计算问题。

表单通过 [Login Interaction](app/login/login-interaction.ts) 将焦点、密码显示模式和提交结果归一为唯一场景状态，CSS 表情与动画运行时使用同一状态。优先级为成功/失败及提交中高于密码可见，密码可见高于普通焦点与待机；密码仍可见时，移开焦点不能恢复围观。密码控件及其显隐按钮属于同一焦点区域，鼠标点击、Tab 和 Shift+Tab 在区域内切换不触发退出或重复入场。插画只接收状态与显示标记，不接收、读取或记录密码内容。

用户名框与隐藏密码框的焦点统一解析为 `inputFocus`；字段身份仅由表单持有，不再保留密码输入专属的弯腰、定时包络或焦点样式。蓝色、黑色和黄色共用父场景的同一输入过渡进度与倾斜角，围绕固定落地基线向右斜切，侧边保持平行、顶底保持水平；五官反向抵消斜切以保留圆形眼睛与水平嘴巴。蓝色脸偏右上、瞳孔向右并使用细长惊讶嘴；黑色眼睛位于顶部附近、向右看；黄色整脸略抬高，右上眼睛配向右伸出的短横嘴；橙色不参加倾斜，右上三点脸只包含两颗圆眼和一颗小圆嘴。

输入框之间通过鼠标、Tab、Shift+Tab 或程序聚焦切换，不退出或重播同一关注姿态；持续输入不改变目标姿态。输入与显示密码在同一时钟上从当前值连续过渡，旧鼠标偏移与身体变形不得叠加到稳定输入姿态。显示密码以及提交/结果的优先级保持不变，失败结束按当前显隐和焦点恢复；减少动画直接应用相同的轮廓、倾斜和五官，不只关闭动画后留下默认站姿。

显示密码采用独立参考姿态：紫色（蓝色长条）直立、脸偏左上，瞳孔向右偷看并使用短倒弧嘴；黑色直立、眼睛位于身体中上部，眼距收窄且向上看，不添加嘴巴；橙色闭眼配小倒弧嘴；黄色固定头部，眼睛在右上、横嘴在左下，嘴巴右端接近眼睛下方。瞳孔只在各自眼白内裁剪，不能裁剪整张脸或黄色长嘴。

显示密码是持续场景状态，不是图标点击次数或登录失败事件；离焦、鼠标移动不能覆盖它，提交/成功/失败仍优先，反馈结束后按当前显隐和焦点恢复。参考姿态中的身体比例与横向小偏移使用固定 SVG 支点并保留共同落地基线；停止待机呼吸时回到基准比例，而不是冻结任意呼吸帧。脸部位置、眼白与瞳孔朝向分别定义，几何与表情都需收敛到确定终点。快速显隐从当前姿态继续过渡，不排队回放旧动作；减少动画保留相同的最终五官与站姿，只取消过渡。

输入关注验收对照其参考图，比较用户名与隐藏密码两种聚焦方式的最终截图；测量蓝、黑、黄的实际侧边斜率及共同落地点，不仅比较配置值。检查圆眼未拉斜、蓝色细长嘴、黑色顶部视线、黄色昂头及橙色三点排列；快速框间切换、显隐和反馈恢复后不能留下旧嘴型或倾斜。两种参考姿态都需保留截图回归。

参考姿态验收在真实 LoginPage / Yak UI 中点击“显示密码”，将角色群裁切后等比例对齐参考图，检查黑色眼睛中上部位置、紫色侧脸与反向瞳孔、四个嘴型和遮挡；不把缩小图的压缩边缘当作矢量造型。分别从不同鼠标方向进入、快速显隐、离焦、失败恢复、出场中显示密码，确认稳态一致；普通与减少动画模式最终关键点一致。截图、组件夹具及真实产品验收的范围分开记录。

[LoginPanel](app/login/LoginPanel.tsx) 拥有单次提交生命周期：校验通过才进入提交中，期间阻止重复提交；插画暂停待机呼吸并收敛跟随，不再响应鼠标目标。成功/失败反馈覆盖输入姿态，失败结束后根据当前焦点和显示模式恢复。组件卸载时使旧异步 UI 回调失效并清理反馈等待；这不表示取消了认证请求。减少动画模式下保留即时表情反馈，不执行姿态动画或强制等待反馈时长。

静态验收先启用系统减少动画偏好并刷新真实登录页，检查四个角色可见、共线落地、留白和五官比例；再检查普通桌面、矮屏、平板与小屏布局。恢复动画后检查橙色出场终点衔接，不把独立 SVG 或替代控件夹具截图当成完整产品交互验收。

交互验收覆盖：用户名与隐藏密码统一关注、框间切换不重播、输入框与显隐按钮间的键盘切换、快速反复切换显隐、明文保持时移开焦点、校验失败不发请求、慢请求期间重复 Enter/点击、成功和失败结果覆盖、失败恢复、请求或反馈期间卸载，以及减少动画模式。验证记录区分真实产品、React 组件夹具和静态采样；不使用真实密码作为截图或日志证据。

动效验收使用可控时间逐帧检查起点、转正停留、黑色倒挂经左侧翻身、橙色首次落地与贴地扩大、黄色成长和双眼过渡、最终轮廓衔接。各阶段边界连续，正常速度和慢放分别检查节奏与形变；覆盖不同时间点的输入/显隐/提交中断、隐藏恢复、减少动画双向切换、长帧及卸载。固定无眨眼阶段与原有输入、显示密码、待机姿态对照，随后验证既有跟随和随机眨眼。等时采样不等于物理高刷新率设备或完整产品验收。

### Success Authored Pose

成功沿用 `success` 场景状态与 [LoginPanel](app/login/LoginPanel.tsx) 拥有的单次提交生命周期，不新增业务状态、提交锁或等待窗口。[成功定格](app/login/LoginSuccessPose.tsx) 位于每个角色的独立 SVG 分支；[造型参数](app/login/login-success-pose.ts) 是成功五官的唯一来源，身体复用现有静态基准，不改颜色、站位、地面与遮挡。普通橙色笑嘴和成功笑嘴共用同一路径，不能重新扩大成功嘴。

蓝色保留正常白眼和黑瞳孔，配短浅微笑；黑色保留正常圆眼，不添加嘴巴；橙色使用独立弧形笑眼，配原有开口笑嘴；黄色保留单眼侧脸，右下长嘴伸出身体，只有末端轻轻上扬。不能把四组眼睛统一压扁，不能让黄色成功脸落回普通居中姿态，也不能借用密码可见状态控制成功笑眼。

[成功过渡](app/login/login-success-transition.ts) 从提交时实际显示的矢量姿态直接进入成功定格，复用父场景的同一 RAF。共享 [Login Pose Snapshot](app/login/login-pose-snapshot.ts) 只负责根 SVG 坐标采样、几何插值和绘制，不拥有认证或失败时序；失败仍由原有控制器调度。切入包含在既有成功反馈窗口中，不能先闪回默认站姿；过渡层与两端分支同属角色，显隐互斥，不能出现两套人物、眼嘴或地面跳动。

成功定格后保持原位，直到原有页面进入流程完成；不执行统一弹跳、错峰下沉、人物淡出或新增整页退场。鼠标、焦点、显隐与重渲染不能覆盖或重播成功反馈，不追加局部庆祝动作或随机眨眼。结果覆盖期间可以准备隐藏的普通恢复目标，但不能绘制它。

成功后的页面进入流程异常时，从当前成功画面直接恢复到最新焦点、显示模式或有效指针目标；恢复是纯视觉过程，不新增等待或提交锁。恢复中重试冻结当前可见画面，下一个结果从冻结画面接续，不强行回中。页面或插画隐藏、减少动画与卸载时结束过渡并清理旧任务；重新显示不补播。减少动画即时保留同一目标造型，表单继续跳过强制反馈等待，不让动画结束事件控制认证。

验收先对比四张成功定格与局部五官，再检查输入关注、密码可见、左右指针及失败恢复中重试的切入起点、中间帧和终点。覆盖成功中变更焦点/显隐、长时间保持、隐藏/响应式恢复、减少动画双向切换、快速重试、页面进入失败与卸载；同时回归入场、普通跟随和失败反馈。静态 SVG 对照保存在 [成功表情夹具](../../scripts/fixtures/login-success/)，只用于评审，不进入产品构建；它们是浏览器画面的矢量提取，不替代动画或真实认证验收。纯几何回归命令由 [Tooling](../../docs/tooling.md#tests) 维护，一次执行结果放在 PR / CI。

### Failure Static Pose

失败沿用 `failure` 场景状态与表单拥有的单一反馈窗口，不新增业务状态、独立等待或提交锁。总时长由 [Login Interaction](app/login/login-interaction.ts) 统一定义，局部动作与末尾定格按同一比例调整，不只延长静态等待，也不单独延长某个角色。字段校验失败仍只显示字段错误，不触发整组失败造型；减少动画不新增强制等待。已确认的静态造型是局部动作的起止基准，不表示永久停留到下一次点击。

失败姿态由各角色私有 SVG 分支完整定义：蓝色保持固定折腰轮廓，上部偏右的小白眼睁开、瞳孔向右，配短倒弧嘴；黑色身体缩矮且近直立，正常尺寸白眼位于新上沿附近、视线偏上，不显示失败嘴；橙色复用饱满半圆，右侧两颗圆眼睁开、配小倒弧；黄色复用固定圆顶，单眼睁开、右下方为短波浪嘴。保留角色遮挡顺序和共同地面。造型参数只在代码维护。

失败造型继续由独立分支拥有，局部动作不受普通偏移污染。进入与恢复由登录页私有 [login-failure-transition](app/login/login-failure-transition.ts) 在同一 RAF 中绘制短暂的矢量过渡层：进入起点采集正在显示的身体、五官与眨眼，而不是默认站姿；对身体路径、眼睛位置/尺寸、裁剪瞳孔和嘴型插值，不用整组淡入淡出替代几何衔接。过渡层与两套端点分支同属各角色，遮挡顺序不变；所有采样转换到根 SVG 坐标，不用变化中的包围盒重定位地面。普通/失败分支保留可测量布局，用透明度互斥绘制；不把失败或过渡节点放进普通 rig 的变换子树。两端准确交回原分支，稳态造型仍只有原实现一个来源。

局部动作由 [login-failure-motion](app/login/login-failure-motion.ts) 按本次失败经过时间纯采样，父场景复用同一 RAF。蓝色眼睛和嘴巴共同做两次幅度递减的左右位移与小幅转动，原脸部倾角保留；黑色单眼围绕自身固定中心闭合、停顿、睁开，眼白和裁剪瞳孔一起参与；橙色两颗圆眼同步短开合两次，嘴巴不动；黄色仅改变短波浪嘴内部控制点，端点、单眼和身体不动。进入过渡结束后的局部反应与末尾定格期间，四个身体保持固定，不恢复整身抖动。完成时准确清除附加变换并恢复原始嘴型，动作早于表单反馈窗口结束，最后保留稳定定格。

每次进入 failure 只播放一次，不因鼠标、焦点/显隐变化或组件重渲染重播；持续保持 failure 时完成后停在基准。离开后再次失败才创建新起点。失败局部开合不是随机眨眼，useLoginAmbientBlink 的 failure 资格继续为空，旧随机动画在进入时取消。局部动作不能释放提交锁、恢复业务状态或等待动画结束事件，不增加凭证数据访问。

失败可结束未完成的入场并清除额外眼点；显示密码、焦点变化和鼠标移动不能覆盖失败。提交中冻结当前普通姿态，不将指针通道归零；失败覆盖期间继续采样指针，并按当前焦点/显隐准备隐藏的恢复目标，保留跟随值和弹簧速度。反馈结束从当前失败画面直接恢复到密码可见、输入关注或最新有效鼠标目标，只有真实失焦/指针离开等目标无效情形才回中性姿态；禁止“先显示归中的普通分支，再追鼠标”。恢复目标逐帧更新，末帧与普通跟随首帧一致，不重置位置、速度或重播入场。恢复期间语义目标改变或快速重试，从最后绘制的矢量姿态重新衔接；字段身份在同一 inputFocus 内变化不重播。

进入过渡覆盖在既有失败反馈窗口内，局部动作采样与末尾定格时序不变；恢复是反馈解锁后的纯视觉阶段，不新增业务状态、认证等待或提交锁。恢复完成事件只用于重新安排普通眨眼，不控制请求。页面/插画隐藏、开启减少动画或卸载时结束过渡并清理旧任务；重新显示或关闭偏好不补播同一次失败。减少动画即时呈现相同端点，仍跳过强制等待。

验收以同一静态失败图为起点/终点基线，逐帧检查蓝色局部往返、黑色闭眼停留、橙色双眨和黄色单轮波形；局部反应与定格期间身体路径不变，进入/恢复期间地面不变。覆盖不同指针方向、输入/显隐及入场/随机眨眼中进入，失败中重渲染不重播，完成后长时间保持基准，快速重试正确重新计时；检查长帧、隐藏/响应式恢复、减少动画双向切换、卸载、多实例及旧回调。退出后回归普通跟随、两套已确认姿态、随机眨眼与成功反馈，核对反馈恢复与重试解锁使用统一时长；修改时长后对比等比例时间点的动作参数与幅度，确认局部动作提前完成且保留末尾定格，成功反馈时长不受影响。可控时间组件、原生时钟录像、真实认证链路和跨浏览器验收分别记录，不将静态起止一致等同于全程像素不变。补充固定鼠标左/右、反馈期间换方向、Enter 保持字段焦点、明文保持、恢复中重试/显隐、眨眼或入场中失败，以及缩放后的进出逐帧检查；比较交接帧身体轮廓与眼睛位置，确认没有中性中间站、双重角色或地面跳动。纯几何回归入口见 [verify-login-failure-transition](../../scripts/verify-login-failure-transition.mjs)，不能用它替代浏览器与真实认证验收。

### Authored Pose Ambient Blink

定格姿态的眨眼由登录页私有 [useLoginAmbientBlink](app/login/useLoginAmbientBlink.ts) 维护，不新增业务场景。输入关注时蓝、黑、黄、橙分别随机眨眼；显示密码时只允许蓝、黑、黄眨眼，橙色持续闭眼弧线不被打开。每个角色的双眼同时开合，不同角色独立安排时间；姿态先稳定再发生第一次眨眼，每次完成后重新抽取等待时间，不按固定顺序轮播或补播积压动作。普通待机中蓝黑独立随机眨眼，橙色保留既有周期，黄色不增加待机眨眼；资格、节点和节奏都按角色及场景匹配，不能把橙色固定周期套给蓝黑。

开合只作用于单眼的局部图形。蓝黑眼白、瞳孔和原裁剪一起变换，绕各自眼睛的固定局部中心闭合；橙黄黑点眼睛局部压缩。身体、脸部位置、眼距、嘴型和瞳孔目标方向不变，眨完恢复原来的观察或偷看视线；不得复用 result-eyes 变换、移动五官或将眨眼写成登录失败状态。

场景统一持有一个等待计时器，单次开合交给浏览器动画，不另建角色 RAF 或逐帧 React 状态。入场期间停止等待，收到同一时间线的完成标记后才重新安排首个周期，不读取旧 CSS 动画或另写一份入场时长。用户名与隐藏密码同属 inputFocus，框间切换和持续输入不重置眨眼安排。显隐切换、提交与结果、卸载时取消旧等待及正在开合的眼睛；取消只移除眨眼叠加，不强制睁眼或改写基础表情。页面隐藏、插画被响应式布局隐藏或减少动画时停止，恢复后重新等待，不残留半闭眼或补播；不接收凭证内容。

验收使用可控随机数和时钟覆盖等待、闭合、睁开、重排间隔以及两眼同步、角色错峰；固定无眨眼阶段对照两套已确认截图。分别录制输入关注与显示密码的持续片段，确认嘴巴、站姿、眼距和原视线不变，橙色显隐期间不被旧回调打开。检查眨眼中快速显隐、框间切换、提交/失败恢复、页面隐藏恢复、运行中开关减少动画、响应式隐藏与卸载；模拟时钟、组件截图与真实产品验收分开记录。

### Blue / Black Pointer Gaze

蓝色（实现中的 purple）与黑色在出场结束后的普通待机中固定身体路径、位置和比例，不叠加指针驱动的倾斜、拉伸或循环呼吸。输入关注与显示密码继续使用已确认的目标姿态；入场仍由入场层承担，成功使用独立定格分支与过渡；失败使用独立分支，身体固定、局部动作单次播放，不给角色根节点统一清空变换。

普通脸部的整组位移与眼白内部的瞳孔偏移分开。父场景复用同一次指针采样及 RAF，以根 SVG 逆矩阵和各自固定脸部中心计算目标；不能用移动中的五官或眨眼包围盒作为参考。两眼及蓝色小嘴共同平移并保持眼距，允许有界的小幅眼线倾角；蓝色普通嘴型不变，黑色不增加普通嘴巴。瞳孔限制在眼白范围内，并使用实例唯一的单眼裁剪；整只眼睛不越出身体可见区域。

普通眨眼复用 useLoginAmbientBlink，匹配当前可见的 idle 眼睛。眨眼层与脸部平移、瞳孔追踪和 result-eyes 分开；闭合期间仍更新观看目标，睁开后呈现当前视线，不重置到正脸。鼠标移动不重排眨眼等待；出场未完成或眼睛暂不可用时重新等待，不播放积压动作或遗留无限等待槽。

输入、显示密码和结果优先于普通追踪，普通偏移按既有姿态权重退出；移出文档、失焦、页面隐藏及触摸后清除悬停目标。减少动画取消追踪与眨眼并保留对应静态姿态；首次以减少动画挂载后关闭偏好，也必须启动同一 RAF，不能重播出场或重复监听。

验收覆盖左右/上下及四角的身体路径与屏幕矩阵不变、两眼间距稳定、瞳孔方向和裁剪、蓝色小嘴联动、眨眼中移动鼠标、缩放与滚动、快速反向、失焦和隐藏恢复、减少动画双向切换及卸载。固定随机数与时钟检查蓝黑独立节奏、双眼同步和橙色周期兼容；对输入和显示密码保留几何与截图回归。区分像素边缘抗锯齿差异和真实几何变化，记录局部组件与真实产品验收边界。

### Orange Pointer Gaze

橙色普通鼠标跟随由 [LoginCharacters](app/login/LoginCharacters.tsx) 私有维护。父场景统一采样指针并调度 RAF，以根 SVG 屏幕矩阵逆变换和橙色静态脸部中心计算目标，不用左侧场景中心或移动后的眼睛作为参考。指针离开文档、窗口失焦或页面隐藏后清除目标；触摸不产生悬停跟随。

圆眼与普通笑嘴共用整脸位移、固定旋转中心和同一弹性时间步。向左看时左眼略高，向上看时回正，向右看时右眼略高；眼距保持稳定，不叠加眼睛独立追踪、整组缩小或嘴巴单独旋转。限制整脸活动范围，极端方向也不能将眼睛或笑嘴推出半圆；普通笑嘴保持紧凑，不能更改输入态圆嘴或显示密码的闭眼倒弧嘴。

身体只以轻微的顶部抬升和控制点变化配合视线，底部端点固定，不叠加循环呼吸缩放、速度驱动的鼓动或整身摇摆。普通眨眼绕每只眼睛自身中心短暂闭合，不改变眼距、笑嘴或整脸朝向；显示密码继续使用独立闭眼弧线。橙色待机眨眼与定格姿态眨眼由同一调度维护，离开待机时不叠加旧周期；页面隐藏或减少动画时全部停止。输入、显示密码与结果状态优先于鼠标，使用已有场景权重收敛，减少动画保留静态表情。

验收对照原视频的左上、上方、右上连续扫视与眨眼：先看整脸方向和眼嘴关系，再看轻微身体配合。覆盖极端四角、下方、快速反向、停止后稳定、离窗回位、缩放和滚动坐标、减少动画及卸载；同时比较统一输入态与显示密码态的基线截图，不能以改善普通笑脸为由改动已确认姿态。数值边界、独立组件录像与真实登录页验收分别记录。

### Yellow Character

[YellowCharacter](app/login/YellowCharacter.tsx) 是登录页私有角色，不进入 Yak UI。普通鼠标跟随不修改黄色身体路径，也不执行待机呼吸或焦点缩放。输入关注是明确的例外：身体沿用固定路径，在父场景共享进度下围绕落地基线整体斜切，脸部独立昂头；这不是恢复鼠标驱动的头壳变形。入场仅由专属时间线临时改变身体路径与过渡五官，完成或中断后恢复固定路径和既有单眼；成功使用独立侧脸定格分支，不缩放或下沉整个角色；失败固定单眼与身体，短波浪嘴只做一次局部形变后恢复基准。保留四个角色的遮挡顺序。

普通跟随中的眼睛和嘴型共用整脸位移及连续的左右朝向参数，不给眼睛追加独立指针位移，也不通过负缩放翻转整张脸。换向区保留中性缓冲，上下两侧都按左右方向换脸，不使用未定义零点的“超过 90°”硬切换。约束整脸位移以保证眼睛在头部安全区域内；长嘴允许有界地伸出黄色轮廓，不能裁剪整个 Face。

父场景统一采样指针并调度 RAF，角色以根 SVG 的屏幕矩阵逆变换及自身固定参考点计算姿态，不使用移动后的五官或动画包围盒作为参考。窗口失焦、指针离开文档或页面隐藏时清除黄色指针目标；触摸不提供悬停跟随。输入与密码隐显使用确定姿态，提交和结果忽略指针；减少动画模式停止跟随并保留静态表情。角色不接收凭证内容。

验收包括：左右/上下移动、从左上和左下分别跨到右侧、中心及分界附近抖动、快速反向、离开窗口、隐藏后恢复、缩放及滚动后坐标、输入/密码隐显/提交/结果覆盖、减少动画及卸载清理。对照黄色局部与完整角色群检查外轮廓不变、五官共同位移、嘴巴连续换边、眼睛不越界及遮挡；模拟帧率和独立组件检查不能代替真实产品验收。
